|**2026-06-15 — Thinking overlay reasoning chunks fix**
|- **Problem**: `ToolReasoningChunkGenerated` events (from tool-plan streaming during `tool_use` loop) were updating the timeline `ToolCallStarted` reasoning but NOT `liveReasoningByClientId`. The `ThinkingOverlay` reads from `liveReasoningByClientId`, so tool-loop reasoning never appeared in the thinking card.
|- **Root cause**: The handler for `ToolReasoningChunkGenerated` in `App.tsx` (SSE event listener) only called `setTimelineByClientMessageId` to update the timeline event, then returned early. It never called `setLiveReasoningByClientId`, which is what the `ThinkingOverlay` reads via `liveReasoning={activeClientMessageId ? liveReasoningByClientId[activeClientMessageId] || '' : ''}`.
|- **Fix**: Added `seenThinkingRef.current.add(clientId)` and `setLiveReasoningByClientId(prev => ({...prev, [clientId]: fullReasoning}))` to the `ToolReasoningChunkGenerated` handler in `App.tsx` so the thinking overlay receives tool-loop reasoning chunks in real time.
|- **Also preserved**: The `ThinkingChunkGenerated` handler (for open-ended thinking via `generateStreamingThoughtsStructured`) still updates `liveReasoningByClientId` independently.
